Linuxインストール環境について

  • ベアメタル

    • ハードウェア上に直接インストール

  • ハイパーバイザー

    • Type1：ハードウェア上にハイパーバイザー専用OSをインストールし、ハイパーバイザーで起動した仮想マシンにインストール、高速、ESXi(VMware)など
    • Type2：ホストOS上にハイパーバイザーソフトウェアをインストールし、ハイパーバイザーで起動した仮想マシンにインストール、低速、VirtualBox(Oracle)など

  • クラウド(IaaS)

    • クラウドサービスで起動した仮想マシンにインストール、EC2(AWS)など

ベアメタルとは

ベアメタルとはまっさらな物理サーバーを指す

  • メリット

    • 物理サーバーに対して単一のOSを直接インストールするため、ハードウェアの処理能力を存分に引き出せる
      • 仮想マシンはハードウェアとの間にハイパーバイザーの余計な処理を挟むため、ベアメタルほど高速に処理できない

  • デメリット

    • ハードウェアに余剰リソースが生まれてしまう
      • 仮想マシンなら他の仮想マシンに余ったリソースを共有できる
    • スナップショットなど仮想マシンならではの機能が使えない

デュアルブート

  • 一つのハードウェアに複数のOSをインストールすることをデュアルブートという
  • デュアルブートする場合、ハードディスクを分割し、それぞれの領域(パーティション)に異なるOSをインストールする

Ubuntuの基本操作

ソフトのインストール

apt-getコマンドを使う

sudo apt-get install apache2

起動など

起動や自動起動などはsystemctlコマンドを使う

sudo systemctl enable apache2 #自動起動
sudo systemctl start apache2 #起動

ハイパーバイザー

ハードウェアを真似（エミュレート）した仮想マシンを提供するソフトウェアのこと。 Type 1とType 2がある。

  • OSはハードウェアに直接インストールする前提で作られている

  • 仮想マシンはハードウェアのマネをしてOSをだます

  • メリット

    • 1台の物理サーバーに対して複数台の仮想マシンを起動できるため、余っているリソースを共有できてムダがない
    • スナップショット、マイグレーションなど仮想マシン独自の機能が使用できる

  • デメリット

    • 仮想マシンはハードウェアとの間にハイパーバイザーの余計な処理を挟むため、ベアメタルほど高速に処理できない

Type 1

ハードウェア上にハイパーバイザー専用OSをインストールし、ハイパーバイザーで起動した仮想マシンにインストールする。 また、Type2に比べて高速であるため、商用の仮想マシンはType1を使用する

  • 例
    • ESXi(VMware)
    • Hyper-V(Microsoft)
    • Xen(Citrix)
    • KVM(OSS)
    • OpenStack(OSS)
    • Proxmox(OSS)

Type 2

ホストOS上にハイパーバイザーソフトウェア(仮想化ソフト)をインストールし、ハイパーバイザーで起動した仮想マシンにインストール。 Type1に比べて低速ではあるが、手軽に使用できるため検証環境などで使用される。

  • 例
    • VirtualBox(Oracle)
    • VMware Workstation(VMware):Windows向け
    • VMware Fusion(VMware):macOS向け

VirtualBoxについて

Oracleが開発するType2のハイパーバイザー。 Windows、macOS、Linuxなどにインストールし、VirtualBox上に仮想マシンを起動できる。

  • 機能
    • 仮想マシン：ハードウェアエミュレート
    • 仮想ネットワーク：仮想的なネットワークを作れる、詳細は後述
    • スナップショット：簡易的なバックアップ、ある時点のディスクイメージ
    • 共有フォルダ：ホストOSとゲストOS間で共有できるフォルダ
      • ホストOS：VirtualBoxをインストールする親のOS、上記例のWindows
      • ゲストOS：仮想マシンにインストールする子のOS、上記例のLinux
    • クリップボード共有：ホストOSとゲストOS間でクリップボードを共有
    • エクスポート・インポート：仮想マシンを簡単に他のホストOSに移植できる

VirtualBoxネットワーク

  • ブリッジ：ゲストOS⇔物理マシンの外、ゲストOSは直接通信
  • NAT：ゲストOS⇔物理マシンの外、ゲストOSはNATされて通信
  • ホストオンリー：ゲストOS⇔ホストOS、ゲストOS⇔ゲストOS
  • 内部ネットワーク：ゲストOS⇔ゲストOS
  • その他のネットワーク
    • 汎用ドライバー
    • NATネットワーク
    • クラウドネットワーク

ブリッジ

  • ゲストOS⇔物理マシンの外
  • ゲストOSは仮想スイッチを通して直接通信
    • ゲストOSはホストOSと同じネットワークに直接接続

NAT

  • ゲストOS⇔物理マシンの外
  • ゲストOSは仮想ルータでNATされて通信
    • NAT：ネットワークアドレス変換
    • ゲストOSのIPアドレスはホストOSのIPアドレスに変換されて、物理マシンの外のホストと通信

ホストオンリー

  • ゲストOS⇔ホストOS、ゲストOS⇔ゲストOS
  • 内部に閉じた通信に使用（物理マシンの外とは通信できない）
  • ホストオンリーアダプターを複数作成することも可能

内部ネットワーク

  • ゲストOS⇔ゲストOS
  • 内部に閉じた通信に使用（物理マシンの外とは通信できない）
  • ホストOSからも切り離されたゲストOS同士の通信に使用
  • VLANのように複数の内部ネットワークに分けることも可能

クラウド(IaaS)

リソースやそのリソースを元に作られたサービスをインターネット越しにレンタルして使用する

  • リソース：CPU、メモリ、ディスクなど

  • サービス：仮想マシンサービス、DBサービスなど

  • メリット

    • その時に必要な分だけをレンタルすれば良いのでムダがない
      • 急にアクセスが増えた場合すぐにリソースを増やせる
      • 急にアクセスが減った場合すぐにリソースを減らせる
    • 初期投資を抑えられる
    • 運用保守の手間が省ける

EC2

  • AWSの仮想マシンサービス
  • 仮想マシンのことをインスタンスと呼ぶ
  • インスタンスタイプによってスペックが決まる
    • CPUの性能、個数、メモリの容量など
    • CPU特化型、GPU特化型など
  • AMI(Amazon Machine Image)でOSやアプリケーションが決まる
    • Amazon Linux、Ubuntuなど
  • セキュリティグループ(ファイアウォール)で通信可能なIPやプロトコルを制限できる
    • SSHとHTTPのみなど

Zabbix概要

統合監視ソフト

運用監視業務で使用するシステム全体の状態を監視し、可視化(グラフ化)するソフトのこと。 代表的なものにZabbix、Nagios、CloudWatch、Datadogなどがある。

Zabbix

  • ラトビアで開発されたオープンソースの統合監視ソフト
  • LAMP構成で動作する
    • L（Linux）、A（Apacheなど）、M（MySQL、MariaDBなど）、P（php）
  • サーバー構築後はブラウザからGUIで操作する
  • 監視対象にZabbixエージェントをインストールしていると高度な監視が可能
    • Zabbixサーバー：tcp/10051
    • Zabbixエージェント：tcp/10050
  • ネットワーク機器などはエージェントレスでSNMPで監視可能

Windwos Server

ドメインコントローラー

ネットワーク上のユーザーやコンピュータを管理する重要なサーバーです。

共有フォルダー

複数のコンピューターからアクセスできる設定が施されたストレージです。

グループポリシー

Windowsのグループと組織単位（OU）

  • グループ：

    • ユーザやサブグループのメンバーにファイルはフォルダへの「アクセス許可」を設定する
    • ユーザやグループをまとめる

  • 組織単位（Oorganization Unit）

    • メンバーとなるユーザやコンピュータに「システムの作業に関する制限」を割り当てるために使う
    • ユーザやグループをまとめる
